🔑 Key Points
  • Access Port — พอร์ตที่ต่อกับ End Device (PC, IP Phone)
  • Trunk Port — พอร์ตที่ส่ง Traffic หลาย VLAN (Switch-to-Switch, Switch-to-Router)

🌳 STP — Spanning Tree Protocol
STP ป้องกัน Switching Loop ใน Layer 2 Network โดยการ Block Port บางพอร์ตเพื่อสร้าง Loop-Free Topology
📋 STP Port States
  • Blocking — รับ BPDU เท่านั้น ไม่ Forward Frame
  • Listening — ส่ง/รับ BPDU เริ่มเลือก Root Bridge
  • Learning — เรียนรู้ MAC Address
  • Forwarding — Forward Frame ปกติ
  • Disabled — Port ถูกปิด
⚡ STP Variants
  • STP (802.1D) — Original, ช้า (30-50 sec)
  • RSTP (802.1w) — Rapid, เร็วขึ้น (1-2 sec)
  • MSTP (802.1s) — Multiple Instance STP
  • PVST+ — Cisco Per-VLAN STP
  • Rapid PVST+ — Cisco Rapid PVST

🗺️ Routing Protocols — OSPF, BGP, EIGRP
OSPF (Open Shortest Path First) — Link State Protocol ใช้ Dijkstra Algorithm คำนวณ Shortest Path ทุก Router มีแผนที่ Network เหมือนกัน (LSDB)
🔑 OSPF Key Concepts
  • Router ID — ตัวระบุ Router ใน OSPF (32-bit)
  • Area — กลุ่ม Router Area 0 คือ Backbone
  • DR/BDR — Designated Router ใน Broadcast Network
  • LSA — Link State Advertisement ข้อมูล Topology
  • LSDB — Link State Database แผนที่ Network
  • Metric = Cost — 100Mbps/Bandwidth (default)
  • AD = 110 — Administrative Distance
! กำหนด OSPF Router(config)# router ospf 1 Router(config-router)# router-id 1.1.1.1 Router(config-router)# network 192.168.1.0 0.0.0.255 area 0 Router(config-router)# network 10.0.0.0 0.255.255.255 area 1 ! Passive Interface (ไม่ส่ง Hello) Router(config-router)# passive-interface Gi0/0 ! ปรับ Cost Router(config-if)# ip ospf cost 10 ! ดู OSPF Neighbor Router# show ip ospf neighbor Router# show ip ospf database Router# show ip route ospf
BGP (Border Gateway Protocol) — Path Vector Protocol ใช้สำหรับ Inter-AS Routing (ระหว่าง ISP) BGP คือ Protocol ที่ทำให้ Internet ทำงานได้ เป็น Protocol ที่ซับซ้อนและทรงพลังที่สุด
🔑 BGP Key Concepts
  • AS (Autonomous System) — กลุ่มเครือข่ายที่มีนโยบาย Routing เดียวกัน
  • iBGP — BGP ภายใน AS เดียวกัน
  • eBGP — BGP ระหว่าง AS ต่างกัน
  • BGP Peer/Neighbor — ต้อง Configure แบบ Manual
  • AS-PATH — รายการ AS ที่ Route ผ่านมา
  • MED — Multi-Exit Discriminator เปรียบเทียบ Route ใน AS เดียวกัน
  • AD = 20 (eBGP) / 200 (iBGP)
! กำหนด BGP Router(config)# router bgp 65001 Router(config-router)# bgp router-id 1.1.1.1 ! กำหนด eBGP Neighbor Router(config-router)# neighbor 203.0.113.1 remote-as 65002 ! กำหนด iBGP Neighbor Router(config-router)# neighbor 10.0.0.2 remote-as 65001 ! Advertise Network Router(config-router)# network 203.0.113.0 mask 255.255.255.0 ! ดู BGP Table Router# show ip bgp Router# show ip bgp summary Router# show ip bgp neighbors
EIGRP (Enhanced Interior Gateway Routing Protocol) — Cisco Proprietary Hybrid Protocol ผสมระหว่าง Distance Vector และ Link State ใช้ DUAL Algorithm คำนวณ Loop-Free Path
🔑 EIGRP Key Concepts
  • DUAL — Diffusing Update Algorithm ป้องกัน Loop
  • Successor — Best Route ไปยัง Destination
  • Feasible Successor — Backup Route พร้อมใช้ทันที
  • FD / RD — Feasible/Reported Distance
  • Metric — Bandwidth + Delay (default)
  • AD = 90 (internal) / 170 (external)
  • Hello/Hold Timer — 5s/15s (LAN), 60s/180s (WAN)

🌐 NAT — Network Address Translation
+

NAT แปลง Private IP เป็น Public IP เพื่อให้อุปกรณ์ภายในเครือข่ายสามารถเข้าถึง Internet ได้ — แก้ปัญหาการขาดแคลน IPv4 Address

1
PC ส่ง Packet ออก
Src: 192.168.1.10:5000 → Dst: 8.8.8.8:80
2
Router ทำ NAT Translation
แปลง 192.168.1.10:5000 → 203.0.113.1:12345 (Public IP)
3
Packet ออกไป Internet
Src: 203.0.113.1:12345 → Dst: 8.8.8.8:80
4
Response กลับมา
Router ค้นหา NAT Table → แปลงกลับ → ส่งให้ 192.168.1.10:5000

🚦 ACL — Access Control List
+

ACL คือชุดกฎควบคุม Traffic ที่อนุญาตหรือปฏิเสธ Packet ตาม Source/Destination IP, Port, Protocol

📌 หลักสำคัญ: ACL ถูก Process แบบ Top-Down — Match Rule แรกที่เจอจะถูก Execute ทันที และท้าย ACL จะมี Implicit Deny All เสมอ
ACL Types
  • Standard ACL (1-99) — กรองด้วย Source IP เท่านั้น วาง ใกล้ Destination
  • Extended ACL (100-199) — กรองด้วย Src/Dst IP + Port + Protocol วาง ใกล้ Source
  • Named ACL — ตั้งชื่อ แก้ไขได้ง่ายกว่า

Extended ACL Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 80 Router(config)# access-list 100 permit tcp 192.168.1.0 0.0.0.255 any eq 443 Router(config)# access-list 100 deny ip any any log ! Apply บน Interface Router(config-if)# ip access-group 100 in

🔍 DNS — Domain Name System
+
DNS คือ "สมุดโทรศัพท์" ของ Internet — แปลงชื่อ Domain เป็น IP Address เช่น google.com → 142.250.x.x
📋 DNS Record Types
  • A — Domain → IPv4 Address
  • AAAA — Domain → IPv6 Address
  • CNAME — Alias → Domain
  • MX — Mail Server Record
  • NS — Name Server Record
  • PTR — IP → Domain (Reverse)
  • TXT — Text Records (SPF, DKIM)
🔄 DNS Resolution Process
  • 1. ค้นหา Cache (Local / Browser)
  • 2. ถามผ่าน Recursive Resolver (ISP)
  • 3. ถาม Root Name Server (.)
  • 4. ถาม TLD Server (.com, .th)
  • 5. ถาม Authoritative Server
  • 6. รับ IP Address กลับมา
  • 7. Cache ผลลัพธ์ (TTL)
⚖️ QoS — Quality of Service
+
QoS จัดลำดับความสำคัญของ Network Traffic — ทำให้ VoIP/Video ไม่กระตุก แม้ Link จะ Congested
📊 Traffic Classification
  • Voice (EF) — VoIP, ต้องการ Low Latency <150ms
  • Video (AF4) — Video Conference, ต้องการ Consistent Bandwidth
  • Critical (AF3) — Business Apps, ERP, SAP
  • Best Effort (BE) — HTTP, Email, ทั่วไป
  • Scavenger — P2P, ความสำคัญต่ำสุด
🛠️ QoS Mechanisms
  • Classification — จัดกลุ่ม Traffic (DSCP, CoS)
  • Marking — ติด Label บน Packet
  • Queuing — CBWFQ, LLQ จัดลำดับ Queue
  • Policing — Drop Packet ที่เกิน Rate
  • Shaping — ชะลอ Packet ที่เกิน Rate
  • Compression — ลดขนาด Header

🌍 BGP Advanced — Path Selection & Policy

จัดระเบียบการเลือกเส้นทาง BGP, policy control และตัวอย่าง config ที่ใช้จริงในงาน Multi-homing, ISP Peering, Data Center EVPN และ SD-WAN

🧭 BGP Best Path Selection
BGP ไม่ได้เลือกเส้นทางจาก bandwidth โดยตรง แต่เลือกตาม Attribute เป็นลำดับชั้น ถ้าเงื่อนไขแรกเสมอกันจึงค่อยดูเงื่อนไขถัดไป
1. Weight

Cisco local-only, ค่าสูงกว่า preferred. ใช้บังคับ outbound path บน router เครื่องเดียว

2. Local Preference

กระจายใน iBGP ภายใน AS, ค่าสูงกว่า preferred. ใช้เลือกทางออก Internet หลัก

3. Locally Originated

Route ที่ originate จาก router เองจะชนะ route ที่เรียนจาก peer

4. AS-PATH Length

AS-PATH สั้นกว่า preferred. ใช้ prepend เพื่อทำ inbound traffic engineering

5. Origin Type

IGP ชนะ EGP และ Incomplete. พบได้บ่อยกับ route ที่ redistribute เข้ามา

6. MED

ค่าน้อยกว่า preferred. ใช้บอก AS เพื่อนบ้านว่าควรเข้าทางไหนเมื่อมีหลาย link

7. eBGP over iBGP

เส้นทางจาก eBGP จะถูกเลือกก่อน iBGP เมื่อ attributes ก่อนหน้าเท่ากัน

8. IGP Metric to Next Hop

next-hop ที่ใกล้กว่าใน IGP จะ preferred. ต้องดู OSPF/IS-IS metric ประกอบ

📐 IPv6 Address Format
IPv6 = 128 bits แบ่งเป็น 8 กลุ่ม กลุ่มละ 16 bits (4 hex) คั่นด้วย : — ย่อได้ด้วย :: แทน consecutive zeros

0000:0000:0000:0001
Interface ID (64 bits) — จาก MAC (EUI-64) หรือ Random
📋 IPv6 Address Types
  • Global Unicast 2000::/3 — เหมือน Public IPv4
  • Link-Local fe80::/10 — Auto-config ทุก Interface
  • Unique Local fc00::/7 — เหมือน Private RFC1918
  • Multicast ff00::/8 — แทน Broadcast
  • Loopback ::1/128 — เหมือน 127.0.0.1
✂️ Shortening Rules
  • ตัด Leading Zeros: 0db8 → db8
  • แทน 0000 ต่อกันด้วย :: ได้ครั้งเดียว
  • 2001:0db8:0000:0000::0001
  • → 2001:db8::1

🔑 BFD Key Concepts

  • Multiplier — กี่ Packet หาย = Down (เช่น 3 = 900ms)

🧠 eBPF คืออะไร?
eBPF = extended Berkeley Packet Filter — ให้เขียนโปรแกรมขนาดเล็กที่รันใน Linux Kernel ได้อย่างปลอดภัย โดยไม่ต้องแก้ Kernel Source Code — ใช้ทำ Networking, Security, Observability
🔥 XDP — eXpress Data Path
  • ประมวลผล Packet ก่อน Network Stack (เร็วมาก)
  • Drop DDoS Packet ที่ Line Rate (~100Gbps)
  • Load Balancer ใน Kernel โดยไม่ต้องผ่าน User Space
  • 3 Modes: Native (NIC Driver), Generic (ทุก NIC), Offloaded (SmartNIC)
  • Cloudflare ใช้ XDP ป้องกัน DDoS ขนาดใหญ่
🐝 Cilium — K8s Network + Security
  • CNI Plugin สำหรับ Kubernetes ที่ใช้ eBPF
  • แทน iptables ด้วย eBPF (เร็วกว่า 3-5x)
  • Network Policy แบบ L7 (HTTP Path, gRPC Method)
  • Hubble — Observability ดู Network Flow ใน K8s
  • ใช้ใน GKE, EKS, AKS เป็น Default CNI

⚡ QUIC & HTTP/3

Transport Protocol รุ่นใหม่จาก Google ที่ใช้ UDP — เร็วกว่า TCP+TLS+HTTP/2 และกำลังแพร่หลายทั่วโลก

📊 Connection Setup: HTTP/2 vs HTTP/3
HTTP/2 (TCP + TLS)
Client ───→ Server: SYN
Client ←─── Server: SYN-ACK
Client ───→ Server: ACK (1 RTT TCP)
Client ───→ Server: TLS ClientHello
Client ←─── Server: TLS ServerHello
Client ───→ Server: TLS Finished (+1-2 RTT TLS)
Client ───→ Server: HTTP GET /
รวม: 3 RTT ก่อนส่ง Data!
HTTP/3 (QUIC + UDP)
Client ───→ Server: QUIC Initial (Crypto)
Client ←─── Server: QUIC Handshake (1 RTT)
Client ───→ Server: HTTP/3 GET /

0-RTT: ถ้าเคยคุยกันแล้ว
Client ───→ Server: 0-RTT + GET / (ทันที!)

รวม: 1 RTT (หรือ 0 RTT)!
✅ QUIC Advantages
  • 0-RTT Connection — คุยกันครั้งแรกได้เลยโดยไม่ต้อง Handshake
  • No Head-of-Line Blocking — Stream แต่ละอันเป็นอิสระ
  • Connection Migration — เปลี่ยน IP/Network โดยไม่ขาด Session (Mobile!)
  • Built-in TLS 1.3 — ไม่ต้อง TLS แยก
  • Better on Lossy Networks — Recovery เร็วกว่า TCP
⚠️ Impact ต่อ Network Engineer
  • Firewall: ต้อง Allow UDP 443 (QUIC) — หลายองค์กรยังบล็อกอยู่
  • QoS: QUIC Encrypt Header — Deep Packet Inspection ไม่ได้
  • Monitoring: NetFlow จะเห็น UDP Port 443 แทน TCP
  • Load Balancer: ต้องรองรับ QUIC Connection ID
  • Browser ที่ QUIC ถูกบล็อกจะ Fallback ไป TCP+HTTP/2 อัตโนมัติ

🆘 Disaster Recovery Networking

⏱ RTO & RPO — Network Context
RTO (Recovery Time Objective) = ระยะเวลาสูงสุดที่ยอมรับได้ที่ Network จะ Down
RPO (Recovery Point Objective) = ข้อมูล Config ที่ยอมสูญเสียได้ (สำหรับ Network = ต้องมี Backup Config ล่าสุด)
🔴 Hot Standby
RTO < 1 นาที — Active-Active ทั้ง 2 DC ทำงานพร้อมกัน
🟡 Warm Standby
RTO 15-60 นาที — DR Site พร้อมแต่ไม่รับ Traffic ปกติ

# Network Compliance Check — CIS Benchmark from netmiko import ConnectHandler import re, json CHECKS = [ {'id':'CIS-1.1','name':'SSH v2 enabled', 'cmd':'show run | include ssh', 'pass_if':'ip ssh version 2'}, {'id':'CIS-1.2','name':'Telnet disabled', 'cmd':'show run | include transport input', 'pass_if':'ssh','fail_if':'telnet'}, {'id':'CIS-2.1','name':'SNMP v3 only', 'cmd':'show run | include snmp-server community', 'fail_if':'public|private'}, {'id':'CIS-3.1','name':'NTP configured', 'cmd':'show run | include ntp server', 'pass_if':'ntp server'}, ] def run_compliance(host, username, password): results = [] with ConnectHandler(device_type='cisco_ios', host=host, username=username, password=password) as conn: for check in CHECKS: out = conn.send_command(check['cmd']) status = 'PASS' if 'pass_if' in check and check['pass_if'] not in out: status = 'FAIL' if 'fail_if' in check and re.search(check['fail_if'], out): status = 'FAIL' results.append({**check, 'status': status, 'output': out}) symbol = '✅' if status=='PASS' else '❌' print(f"{symbol} [{check['id']}] {check['name']}: {status}") passed = sum(1 for r in results if r['status']=='PASS') print(f"\n📊 Score: {passed}/{len(results)} ({passed/len(results)*100:.0f}%)") return results results = run_compliance('192.168.1.1', 'admin', 'secret')
📶 Private 5G / LTE

Enterprise Private 5G สำหรับ Factory, Warehouse, Campus — Network Slicing, MEC, Integration กับ Enterprise WAN

🏗️ Private 5G Architecture
Private 5G ไม่ใช่ WiFi — เป็น Cellular Technology ในพื้นที่ส่วนตัว ให้ Coverage กว้างกว่า, Mobility ดีกว่า, Latency ต่ำกว่า WiFi ในสภาพแวดล้อม Industrial
🔑 Key Components
  • gNB (gNodeB) — 5G Base Station ในพื้นที่
  • 5G Core (5GC) — On-premise หรือ Cloud
  • UPF — User Plane Function (Data Routing)
  • AMF — Access & Mobility Management
  • SIM/eSIM — Authentication แทน WiFi Password
⚡ Network Slicing
  • แบ่ง Network เดียวออกเป็น Virtual Network หลายตัว
  • eMBB Slice — High Bandwidth (Video, AR/VR)
  • URLLC Slice — Ultra-low Latency <1ms (Robot Control)
  • mMTC Slice — Massive IoT Devices (Sensors)
  • แต่ละ Slice มี QoS, Security, Priority แยกกัน
🖥️ MEC — Multi-access Edge Computing
  • ประมวลผล Data ที่ Edge (ใกล้ Device) ไม่ต้องส่งไป Cloud
  • Latency ต่ำกว่า <5ms vs Cloud ~50ms
  • ดีสำหรับ: AMR Robot, Vision QC, Real-time Control
  • รัน Application ที่ MEC Server ติดกับ gNB
✅ Private 5G vs Wi-Fi 6
  • Coverage: 5G ดีกว่าในพื้นที่ใหญ่/กลางแจ้ง
  • Mobility: 5G Handover Seamless ขณะเคลื่อนที่
  • Security: 5G SIM Auth แข็งแกร่งกว่า WPA3
  • Cost: Wi-Fi ถูกกว่าสำหรับพื้นที่เล็ก Indoor
  • Latency: URLLC 5G <1ms vs Wi-Fi ~5-10ms
